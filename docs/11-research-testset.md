# 11 · 按调研比例构造测试集：噪声有哪些、各占多少、校验器表现如何

> 问题：没有真实订单，能不能先调研客户输入里会有哪些噪声、各占多少比例，再在开放数据的标准地址上按这个比例加噪声，当作测试集？
> 做法：**文献 + 实测**确定噪声种类和比例 → 在 **2026 年官方地址表**上按比例构造测试集 → 另用 **8,000 条真实人写地址**直接检验。
> 代码：[`fetch_overture.py`](../mvp/scripts/fetch_overture.py)（下载数据）、[`measure_noise.py`](../mvp/scripts/measure_noise.py)（统计噪声）、[`make_research_testset.py`](../mvp/scripts/make_research_testset.py)（构造测试集）、[`evaluate_real_strings.py`](../mvp/scripts/evaluate_real_strings.py)（真实地址评测）、[`whatif_current_reference.py`](../mvp/scripts/whatif_current_reference.py)（换参考库）
> 报告：[噪声统计](../mvp/reports/noise_stats.md)、[测试集评测](../mvp/reports/labeled_eval_report_research.md)、[真实地址评测](../mvp/reports/real_strings_eval.md)、[换参考库](../mvp/reports/whatif_current_reference.md)

## 1. 结论

| 问题 | 结论 |
|---|---|
| 标准地址从哪来？ | **Overture Maps 的地址数据**（开源，包含 OSM 等来源）。其中新加坡部分来自 OneMap 官方地址表的 **2026 年快照**，共 13.5 万个地址，许可与现用参考库相同（Singapore Open Data Licence）。OSM 自身的下载服务在本环境被网络策略拦截，Overture 可以访问 |
| 噪声种类和比例从哪来？ | 两个来源：**文献**（Baymard 手输地址错拼率、Damerau 字母错拼构成、Verhoeff 数字输入错误构成、新加坡统计局住房结构）；**实测**：用 10.6 万条新加坡商户自填地址（Overture places，主要来自 Facebook 商户主页）与官方地址逐条比对，统计每种噪声出现的比例。没有数据的项单独标为"假设" |
| 测试集长什么样？ | 5,000 条（[`testset_sg_research_v1.csv`](../mvp/labeled/testset_sg_research_v1.csv)），每种噪声按表中比例独立注入；29.2% 至少有一处需要改动地址的错误。**7.4% 是 2026 年有、2017 年参考库没有的真实新地址**，不再是虚构的 |
| 校验器表现 | 调研测试集：自动通过 70.7%，文字足以确定地址时找对 99.2%，误拒 0.7%，静默错误 0.04%（2 条），缺单元号只检出 18.3%。**真实人写地址**（8,000 条）：带邮编时找对 97.9%，误拒 1.2%，静默错误 0 |
| 最大的发现 | **参考库过时是第一大问题**：现在 9.6% 的组屋楼栋不在 2017 参考库里。把参考库换成 2026 年数据，测试集找对率从 86.7% 升到 93.8%，新地址从 0% 升到 95.1%，其他条目不受影响。许可相同，可以直接换 |
| 其他短板 | 缺单元号不提示；真实世界的缩写（`N Bridge Rd`、`Woodlands Xing`、`Seletar Aerospace Vw`）不认识，甚至纠错成另一条路；不在参考库里的楼宇名 / 商户名导致多余确认；`#03-05/06`、`#10th Floor` 这类单元号写法解析失败；马来西亚地址被匹配到新加坡同名道路 |
| 和上一版模拟订单比 | 两份数据发现的问题一致（缺单元号、字母后缀、马来西亚地址、缩写），相互印证。静默错误率差别大（0.33% vs 0.04%）：上一版假设了 App 自动补全会带出错误地址，这一版没有这方面的数据，所以没有模拟。**静默错误率高度依赖输入方式，只能用真实订单确定** |

## 2. 噪声调研

### 2.1 文献

| 来源 | 结论 | 用在哪 |
|---|---|---|
| [Baymard Institute](https://baymard.com/blog/automatic-address-lookup)（大规模可用性测试） | **9%** 的手输收货地址含错拼（街道名、城市名或门牌号） | 道路错拼率的上限参考 |
| [Damerau (1964)](https://en.wikipedia.org/wiki/Damerau%E2%80%93Levenshtein_distance) | **80% 以上**的拼写错误是一次插入 / 删除 / 替换 / 相邻对调 | 字母错拼模型：80% 一次编辑，20% 两次 |
| [Verhoeff (1969)](https://en.wikipedia.org/wiki/Verhoeff_algorithm) | 数字输入错误中，单个数字错 **79.1%**，相邻两位对调 **10.2%**，其他 10.7% | 邮编、门牌号的按键错误模型 |
| [新加坡统计局 2024](https://www.singstat.gov.sg/find-data/search-by-theme/households/resident-households/latest-data) | 常住户 **77.4%** 住组屋、**17.7%** 住公寓、**4.7%** 住有地住宅 | 地址抽样比例（另假设 15% 的订单送到公司） |
| [USPS 退信分析](https://mailingsystemstechnology.com/article-4043-Undeliverable-As-Addressed-Mail-Where-Does-It-Come-From-and-How-Do-You-Fix-It.html) | 无法投递的邮件中 12.5% 是地址要素缺失或错误，多为缺单元号 | 说明缺单元号是主要风险，但没有订单级比例 |
| [行业博客](https://ecomhint.com/blog/address-validation-ecommerce)（二手数据，可信度低） | 约 20% 的线上地址至少有一处错误；约 30% 的派送失败源于缺单元号 / 门牌 | 交叉核对：本测试集 29.2% 有错，比这个口径偏严 |
| [印度电商地址研究](https://arxiv.org/pdf/1802.04625) | 印度 30–40% 的邮编写错 | 仅作对照：新加坡邮编与楼栋一一对应，错误率低得多 |

### 2.2 实测：10.6 万条真实人写地址（[完整统计](../mvp/reports/noise_stats.md)）

**做法**：Overture places 里的新加坡商户地址，按"地址 + 邮编"去重，共 106,241 条。每条取官方地址表里同一邮编的标准地址，逐项比对门牌、道路、邮编、单元号、楼宇名等。

**检测规则经过人工抽检**：
- 第一版把平台缩写（`Everton Prk`、`Nassim Hl`、`Pandan Lp`）误判为错拼，已补充缩写表。
- 第一版把"门牌写在道路后面"（`Hougang Ave 2, #01-181 Block 706`）误判为没写门牌，已单列一类。
- 修正后抽检各类样例，检测都是对的，例如：
  - 邮编错：`7 Hougang Ave 3` 配的是 6 号的邮编。
  - 真错拼：`Bedok Reservior`、`Woodlands Clos`、`Temasek Boulvard`。

| 噪声 | 实测比例 | 例子 |
|---|---|---|
| 邮编缺失 | 3.5%（Meta 1.9% ~ Foursquare 18.2%） | — |
| **邮编属于另一个地址** | **3.0%** | `7 Hougang Ave 3` 配 6 号的邮编；`47B Edgefield Plains` 配 105A 的邮编 |
| 邮编在官方表里查不到 | 1.5% | — |
| 门牌没写 | 5.2% | `Ubi Rd 1`、`Singapore General Hospital` |
| 门牌与邮编对应的不同 | 2.6% | `2 Beach Rd` 配 371 号的邮编 |
| 门牌写在道路后面 | 2.8%（组屋 4.2%） | `Hougang Ave 2, #01-181 Block 706` |
| 道路错拼（可认出） | 1.1% | `Bedok Reservior Rd`、`Woodlands Clos` |
| 只写楼宇 / 商场名，没写道路 | 3.8% | `#B1-23 Junction 8`、`#02-59 Vivo City` |
| 路型词缩写 | Avenue→Ave 87%、Road→Rd 89%、Street→St 65%、Jalan→Jln 61%、North→N 29% | `Bedok N Ave 3` |
| 带单元号 | 46.5% | 写法：`#01-23` 90.1%、`Level 3` 3.4%、`# 01 - 23` 2.3%、`Unit …` 1.0% |
| 带 Blk / Block 前缀 | 组屋 21.4%，非组屋 2.1% | — |
| 带楼宇名 | 33.1%，其中 44% 写在地址前面 | `Plaza Singapura, 68 Orchard Rd` |
| 夹杂中文 | 0.5% | `Thomson Rd, 238号Novena Square` |
| 重复片段 | 0.2% | `Eon Shenton, Eon Shenton, 70 Shenton Way` |

**局限**：商户主页上的地址不等于顾客下单地址。一部分由平台自动格式化，所以缩写比例偏高、大小写几乎都规范。顾客在手机上手输，小写和错拼应当更多。

## 3. 测试集怎么造（[`make_research_testset.py`](../mvp/scripts/make_research_testset.py)）

1. **标准地址**：从 2026 年官方地址表按住房结构抽样。组屋、公寓、有地住宅按统计局比例，另有 15% 送到写字楼（假设）。
2. **按表注入噪声**：每种噪声独立按比例注入，每个比例都在代码的 `NOISE` 表里写明出处，分为"实测 / 文献 / 假设"三类：

   | 噪声 | 比例 | 依据 |
   |---|---|---|
   | 邮编缺失 | 3.5% | 实测 |
   | 邮编错误 | 4.5%（一半是相邻门牌的邮编，一半是按键错误） | 实测；拆分为假设 |
   | 门牌没写 / 写错 | 5.2% / 2.6% | 实测 |
   | 门牌写在道路后面 | 组屋 4.2%、其他 2.4% | 实测 |
   | 道路错拼 | 5% | 文献（Baymard 9%）与实测（1.1%，下限）之间 |
   | 只写楼宇名 | 3.8% | 实测 |
   | 缩写、单元号写法、Blk 前缀、楼宇名位置、中文、重复、大小写 | 见上表 | 实测 |
   | 字母错拼构成 / 数字错误构成 | 80% 一次编辑；79 / 10 / 11 | 文献 |
   | 缺单元号 | 10% | **假设**（没找到订单级比例） |
   | 地址栏混入姓名 / 电话 / 备注 | 5% | **假设** |
   | 非新加坡地址 / 没有地址 | 各 0.5% | **假设** |

3. **标注**：沿用[标注规范](../mvp/labeled/GUIDELINE.md)。只看文字能判断到什么程度，由标注员视角的规则在 2026 年地址表上判断。真实地址不在 2017 参考库里的，标为 `NOT_IN_REFERENCE`（真实新地址）。

**结果分布**：
- 可确定 87.3%、参考库没有 7.4%、矛盾 2.4%、有歧义 1.4%、误导 0.4%、没有地址 / 非新加坡 1.1%。
- 期望结论：ACCEPT 64.8%、CONFIRM 17.9%、FIX 9.9%、补单元号 7.4%。

### 4.1 三份测试集对比

| 测试集 | 地址来源 | 噪声来源 | 条数 | 自动通过 | 可确定时找对 | 误拒 | 静默错误 | 缺单元号检出 |
|---|---|---|---|---|---|---|---|---|

## 5. 发现的问题（按影响排序）

| # | 问题 | 证据 | 建议 |
|---|---|---|---|
| 1 | **参考库过时** | 9.6% 的组屋楼栋、2.9% 的全部地址不在 2017 参考库里；换 2026 年数据找对率 +7.1 个百分点 | **最优先**：参考库换成 OneMap 当前数据（同一许可），并建立月度更新 |
| 2 | 缺单元号不提示 | 调研测试集只检出 18.3%，模拟订单 22.5% | 组屋用邮编规则即可判断为多单元楼；公寓 / 写字楼需要楼栋属性数据（见 [10 文档](10-labeled-data.md)） |
| 3 | 真实世界缩写不认识 | North→N 占 29%；`Woodlands Xing` 被纠成 Woodlands Terrace，不带邮编时 `13 N Bridge Rd` 被纠成 New Bridge Rd；抽样 3,000 条真实地址中 3.7% 因此被要求确认 | 按实测补充缩写表：N / E / W、Vw、Wy、Cr、Xing、Prk、Hl、Grn、Lp、Fld、Gtwy、Clos |
| 4 | 不在参考库的楼宇名 / 商户名 | 真实地址带邮编时 21.4% 被要求确认，最主要原因是未识别文字（抽样中约占这些确认的一半）（`TripleOne Somerset`、`Storefriendly Paya Lebar`） | 邮编 + 门牌 + 道路已确认时，未识别的楼宇名不应阻止直接通过；楼宇名库改用 2026 年数据 |
| 5 | 单元号写法解析失败 | `#02-38/#02-56 City Gate Mall`、`#03-05/06` 直接判 FIX；`#4`、`#10th Floor`、`#11/F` 判格式错误 | 支持多单元号、只写楼层、`10th Floor` / `11/F` 等写法 |
| 6 | 门牌缺失 + 道路错拼时忽略有效邮编 | 5 条：`#14-108 Bdok South Ave 3, Singapore 460166` 被建议成 `3 Toh Avenue`，道路名里的 3 被当成门牌 | 邮编有效且与道路大致吻合时，优先按邮编确定 |
| 7 | 马来西亚地址 | 30.8% 被匹配到新加坡同名道路（Jalan Setia、Jalan Molek） | 识别 Johor / Taman / 5 位邮编等信号，直接判 FIX |
| 8 | 字母后缀冲突 | 漏写字母后缀时一半被误拒 | 见 [10 文档](10-labeled-data.md) |

**置信度的补充发现**：
- 用模拟订单统计的置信度模型，拿到调研测试集上校准反而更差（误差 0.021，旧模型 0.013）。
- 原因是两份数据的错误构成不同。**置信度表不能跨数据分布搬用**，必须用和线上分布一致的真实订单统计。

## 6. 局限

1. **实测来自商户地址，不是顾客订单**：平台格式化让缩写更规范、大小写更整齐；顾客手输的错拼、小写会更多。
2. **仍有假设项**：缺单元号比例、混入非地址信息的比例、非新加坡地址比例、邮编错误里"邻近门牌"与"按键错误"的拆分，都没有找到数据。
3. **没有模拟 App 自动补全**：模拟订单 v1 显示它是静默错误的主要来源，但没有数据说明有多少订单经过自动补全。
4. **真实地址评测是弱标注**：真实地址由邮编推出，只包含邮编与文字不矛盾的记录，所以邮编写错、门牌矛盾这类最难的情况不在其中（由调研测试集覆盖）。
5. **文献原文无法访问**：本环境拦截了 Baymard、Loqate、arXiv 等网站，文献数字来自检索结果摘要，引用时已附原始链接，正式使用前建议核对原文。

## 7. 复现

```bash
cd mvp
pip install -r requirements.txt                 # 新增 pyarrow
python scripts/fetch_overture.py                 # 下载 Overture 新加坡地址与商户数据（约 1 分钟）
python scripts/measure_noise.py                  # 统计真实地址噪声 -> reports/noise_stats.md
python scripts/make_research_testset.py          # 构造调研测试集 -> labeled/testset_sg_research_v1.csv（已提交）
python scripts/evaluate_labeled.py --orders labeled/testset_sg_research_v1.csv \
    --confidence-train labeled/orders_sg_v1.csv --tag _research
python scripts/evaluate_real_strings.py          # 真实人写地址评测
python scripts/whatif_current_reference.py       # 参考库换成 2026 年数据的效果
```

数据许可：
- 地址数据：OneMap 地址（经 OpenAddresses / Overture 发布），Singapore Open Data Licence，署名 Singapore Land Authority。
- 商户数据：Overture places，CDLA-Permissive-2.0。只提交统计结果，不提交原始商户数据。
