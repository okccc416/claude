# 03 · 东南亚数据策略

> 目的：回答"AV 需要什么数据、东南亚各国地址有什么坑、数据从哪来"。
> **一句话：算法决定下限，数据决定上限。** AV 能否"敢说不"，完全取决于你对"什么地址真实存在"以及"我的数据在这里有多全"的把握。

---

## 1. 数据分层（L0–L7）

建议用这张表做内部数据盘点，**每个国家 × 每一层**标注：有 / 无 / 覆盖率 / 时效 / 授权状态。

| 层 | 数据 | 在 AV 中的作用 | 必要性 |
|---|---|---|---|
| L0 | **行政区划**（层级 + 边界 + 历史沿革映射） | 一致性校验、旧地址映射、标准化输出 | 必需 |
| L1 | **邮编库**（邮编 ↔ 行政区 / 街道 / 楼栋） | 一致性校验、邮编推断 / 替换 | 必需 |
| L2 | **路网与街道名**（含别名、旧名、多语言名） | 街道匹配、拼写纠正 | 必需 |
| L3 | **楼栋 / 门牌点**（门牌号 + 坐标 + 楼宇名） | ★ 门牌级存在性判断，达到 `PREMISE` 粒度 | 核心 |
| L4 | **单元 / 子地址**（楼层、单元号、单元数） | 单元级校验，达到 `SUB_PREMISE` 粒度 | 差异化 |
| L5 | **POI / 楼宇属性**（住宅 / 商业 / 楼宇类型） | metadata、地标式地址解析 | 重要 |
| L6 | **行为数据**（搜索 → 选点日志、导航终点、配送签收 GPS、上车点） | 发现新地址、验证存在性、入口点 | 飞轮 |
| L7 | **反馈数据**（客户采用版本、投递成功 / 失败） | 纠错、训练、评测集 | 飞轮 |

### 一个关键但常被忽视的数据：**区域完整度（Coverage Completeness）**

- 在某条街 / 某个邮编区里，你的参考库覆盖了多少比例的真实地址？
- 估算方法：参考库地址数 ÷ 估计真实地址数（可用建筑轮廓数、人口 / 户数统计、配送目的地去重数交叉估计）。
- **用途**：完整度高的区域，"查不到"可以判 `UNCONFIRMED_AND_SUSPICIOUS`（→ FIX）；完整度低的区域，只能判 `UNCONFIRMED_BUT_PLAUSIBLE`（→ CONFIRM）。
- **没有这个指标，你会在数据差的区域大面积误拒好地址。** 建议做成一张内部"覆盖热力图"，也是对外说明覆盖能力的依据。

## 2. 东南亚各国地址特点与难点

| 国家 | 典型结构 | 邮编 | 主要难点 | Google AV |
|---|---|---|---|---|
| 🇸🇬 新加坡 | `[Blk] 门牌 街道, #楼层-单元, 楼宇名, Singapore 邮编` | 6 位，**基本一楼一码** | 单元级（HDB / Condo `#05-12`）、楼宇名别名、中英混写 | GA |
| 🇲🇾 马来西亚 | `No. X, Jalan Y, Taman Z, 邮编 城市, 州` | 5 位，区域级 | **同名街道大量重复**（`Jalan 1/2`、`Jalan SS 2/24`），必须靠 Taman + 邮编消歧；Lot 号、Kampung 地址 | GA |
| 🇮🇩 印尼 | `Jl. X No. Y, RT/RW, Kelurahan, Kecamatan, Kota/Kab, Provinsi, 邮编` | 5 位 | **大量地址无门牌**，依赖 RT/RW 和地标（"depan masjid"）；`Gg.`（小巷）、`Perumahan / Komplek Blok A3 No. 12`；行政区划时有调整（如 2022 年巴布亚新设省） | **未覆盖** |
| 🇹🇭 泰国 | `门牌 Moo X, Soi Y, Thanon Z, Tambon, Amphoe, Changwat, 邮编` | 5 位，约区县级 | 门牌号形如 `123/45`，**不一定沿街顺序编排**；泰文 / 英文转写不统一；Moo（村）与 Soi（巷）组合 | **未覆盖** |
| 🇻🇳 越南 | `Số nhà, Ngõ/Hẻm, Đường, Phường/Xã, (Quận/Huyện), Tỉnh/TP` | 5 位 | **2025-07-01 起省份 63→34、撤销县级、乡级大量合并**：未来数年新旧地址混用；多层小巷（`ngõ/ngách/hẻm 123/45/6`）；用户常**不输入声调符号** | **未覆盖** |
| 🇵🇭 菲律宾 | `Blk X Lot Y, Phase, Subdivision, Street, Barangay, City/Municipality, Province, ZIP` | 4 位 | Block/Lot 式住宅区地址、Purok / Sitio 等非正式单位；Barangay 同名多 | **未覆盖** |

### 几个值得单独展开的"坑"与"机会"

**🇸🇬 新加坡 — 最容易做到极致的市场**

- 邮编≈楼栋，意味着只要邮编库准，`PREMISE` 级校验几乎是"查表"，**真正的战场在单元级**。
- data.gov.sg 上的 HDB 楼栋数据集包含楼栋号、街道、**最高楼层**、住宅 / 商业属性、户数等字段——仅凭"最高楼层"就能识别 `#25-123` 出现在 12 层楼里这种明显错误。
- 私宅（Condo）单元数据更难拿，可通过合作方、行为数据逐步补齐。

**🇻🇳 越南 — 行政区划改革带来的窗口期**

- 2025 年 7 月起，大量地址中的省、县、乡名称已失效，但用户、存量数据库、证件上仍长期使用旧地址。
- **"输入旧地址 → 识别 → 输出新标准地址 + 新旧对照"** 是当地企业的刚需（物流、银行、电商都要迁移存量地址库），且 Google AV 未覆盖越南。
- 需要：完整的新旧行政区划映射表（含"一个旧乡拆入多个新乡"的一对多情况）+ 边界数据用于坐标反查。

**🇮🇩 印尼 / 🇵🇭 菲律宾 — "非正式地址"是常态**

- 不能用"缺门牌号 → FIX"这种欧美逻辑，否则会拒掉大量真实可送达地址。
- 国家规则包需要允许"RT/RW + 地标"或"Block/Lot + Subdivision"作为合法完整地址。
- 地标式地址的校验需要 POI 数据 + 行为数据（该描述对应的历史签收点）。

## 3. 数据来源地图

### 3.1 政府 / 邮政权威数据（需逐一核实授权条款）

| 国家 | 可能的来源 | 备注 |
|---|---|---|
| 新加坡 | SLA OneMap（地址检索 API 与数据）、SingPost 邮编 / 地址数据、data.gov.sg（HDB 楼栋数据等）、URA | OneMap 与 SingPost 数据的商用条款需分别洽谈 |
| 马来西亚 | Pos Malaysia 邮编数据、州政府 / 地方议会门牌数据 | 无全国统一开放门牌库 |
| 印尼 | 内政部（Kemendagri）行政区划代码、BPS 统计区划代码、Pos Indonesia 邮编 | 行政区划代码是一致性校验的基础 |
| 泰国 | Thailand Post 邮编、内政部行政区划 | 泰英双语名称需统一 |
| 越南 | 政府发布的 2025 年行政区划调整方案与新行政单位清单、VNPost 邮编 | 新旧映射是核心资产 |
| 菲律宾 | PSA 的 PSGC（菲律宾标准地理代码）、PHLPost ZIP | PSGC 覆盖到 Barangay |

### 3.2 开放数据（注意许可证）

| 来源 | 内容 | 许可证与风险 |
|---|---|---|
| OpenStreetMap | 路网、部分门牌、POI、建筑 | **ODbL：衍生数据库公开使用有"相同方式共享"义务**，与自有数据混合前务必法务评估 |
| Overture Maps | 地址、建筑、POI、行政区划主题 | 不同主题 / 不同来源许可证不同，需逐源确认 |
| OpenAddresses | 聚合各地开放门牌数据 | 各数据源许可证不一 |
| libpostal | 地址解析模型与训练数据（基于 OSM 等） | MIT（模型代码）；训练数据来源另有许可 |
| Google libaddressinput | 各国地址格式元数据（字段顺序、必填项、邮编正则） | Apache 2.0，可作为国家规则包初始参考 |

### 3.3 商业与合作数据（真正的护城河）

- **物流 / 快递 / 电商 / 外卖 / 网约车合作方**：地址文本 + 实际签收 / 上车 GPS + 成功 / 失败结果。
  这是唯一能大规模回答"这个地址真实存在且能送达、入口在哪"的数据。
- 合作模式：以"免费 / 折扣使用 AV + 投递结果回流"交换数据；注意 PDPA（新加坡个人数据保护法）及各国隐私法——地址 + 人名 + 电话属于个人数据，需脱敏、限定用途、签署数据处理协议。
- **内部数据**：你们自己的地图搜索日志（用户输入 → 最终点选结果）是非常好的解析训练数据和别名来源。

## 4. 参考库建设要点

1. **每条记录可追溯**：来源、许可证标签、采集时间、最近一次被验证的时间、置信度。
2. **许可证隔离**：ODbL 等 share-alike 数据与自有数据在存储和产出上要能隔离，避免"污染"整个库。
3. **冲突消解**：同一地址多来源冲突时的优先级规则（权威 > 行为验证 > 开放数据），冲突本身也要记录。
4. **时效**：新楼盘、拆迁、改名、行政区划调整——设定每国的数据更新 SLA，并监控"新地址首次出现"的速度。
5. **负向知识**：不仅要存"存在的地址"，还要存"已知不存在 / 已拆除 / 已改名"的地址及映射。
6. **区域完整度**：按邮编 / 最小行政单元计算并定期更新（见第 1 节）。

## 5. 国家优先级评估框架

用下表给候选国家打分（1–5 分），辅助决定首发和扩张顺序：

| 维度 | 权重建议 | 说明 |
|---|---|---|
| 市场规模与付费意愿 | 25% | 电商 / 物流体量、客户预算 |
| Google 空白程度 | 20% | 未覆盖 = 5，GA 且质量好 = 1 |
| 我方数据就绪度 | 30% | L0–L4 完整度、有无合作数据 |
| 实现难度（反向计分） | 15% | 地址规范度、语言复杂度 |
| 战略价值 | 10% | 本土市场、标杆客户、政策窗口（如越南改革） |

> 一个常见的推荐组合：**新加坡（本土、数据好、做深到单元级、打造标杆）+ 越南或印尼（Google 空白、做广）**。最终以你们的数据盘点结果为准。
