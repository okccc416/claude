# 17 · 悉尼门址底表体检（对照 G-NAF）

> 数据：悉尼门址底表（Data Agent 的地址向量检索库，421 万条，`vector` 列已去掉），本文先用 5 万条随机抽样（种子 42）。
> 对照：全国门址库里悉尼一带的 G-NAF 门址点（Overture 2026-09-23.1，321.7 万个点）。
> 本文和 `mvp/reports/sydney_base_health_sample.json` 只有汇总数字，没有原始门址。全量结果到了再补第 6 节。

## 1. 结论

1. **底表就是 G-NAF 派生的标准门址表，坐标质量很高。** 96.6% 的门址在 G-NAF 里能找到同路、同门牌的点，坐标在 30 米以内（中位 0.7 米，P90 1.2 米）。算上偏 30–500 米的和只差方位后缀的，97.7% 对得上。
2. **suburb 和邮编可以补齐。** 底表没有这两列；97.9% 的门址可以直接从 G-NAF 补上。同一 district 下的同名门址（全量有 4.5 万组）补上 suburb 后就分得开（抽样里能判断的组全部分开）。
3. **真正要处理的问题约 2.4%**，按影响排：
   - 门牌在 G-NAF 附近找不到：1.7%。其中六成是坐标落在同一条路的另一个门牌上（转角、合并地块、改过号）；还有带字母的门牌（如 12A）G-NAF 只有 12，以及附近没有任何 G-NAF 点的（新建或 G-NAF 快照里还没有）。
   - 路名在附近找不到：0.3%。一部分是把路名写成了公路编号（A28 这类），其余多是新开发片区的新路。
   - 只有地块号的临时地址（LOT n + 路名）：0.2%。其中 86% 在 30 米内已经有 G-NAF 正式门牌，可以直接换掉。
   - 坐标放错地方：0.1%。同路同门牌在 G-NAF 里，但离底表坐标 500 米以上（中位 10.8 公里）。
   - 方位后缀不一致：0.1%。底表少写或多写了 NORTH / EAST 之类的后缀。
4. **district 列不能当 suburb 用。** 大多数是 LGA（议会）名；Wingecarribee、Hawkesbury 一带写的是 locality，但约 8.5% 实际在相邻 suburb。另外 `q`（全量 778 行）实际是 Watsons Bay，`派珀角`（1,451 行）是 Point Piper（中文译名），可以直接改。
5. **两类来源差别不大。** 32 位 hex 编号的行吻合率 97.0%，UUID 编号的 95.8%；UUID 行新路更多（路名找不到 0.48% 对 0.18%）。混合大小写的行（约 5%）坐标精度差一些：偏 30–500 米的占 5.2%，全大写的只有 0.8%。

## 2. 方法

每条底表门址拆出单元、楼层、门牌（含区间 38-48）、路名，在 G-NAF 里找"同路名 + 同门牌"的点：

| 步骤 | 做法 |
|---|---|
| 路名比较 | 用引擎的澳洲路名规范化（类型词缩写展开，`CLOS` → `CLOSE`），再去空格比较（POWDER WORKS = POWDERWORKS） |
| 门牌 | 区间门牌整串、首号、尾号都查；底表写单号而 G-NAF 存区间（16-20 含 18）也算 |
| 方位后缀 | 对不上时去掉 NORTH / SOUTH / EAST / WEST 再比，单独记为"后缀不一致" |
| 附近有没有这条路 | 约 1 公里的格子，查周围 3×3 格 |
| LOT 地址 | 看 30 米内同一条路有没有 G-NAF 正式门牌 |

脚本：`mvp/scripts/base_table_health.py`。同一个脚本可以输出逐行补齐结果（编号、分类、距离、suburb、邮编、官方路名和门牌），给底表回填用。

## 4. 建议（按收益排）

1. **补 suburb 和邮编**：用补齐结果直接回填，约 98% 的门址有值。这是 GU 召回和评测都缺的字段，也让 4.5 万组同名门址不再歧义。
2. **修 district**：`q` → Watsons Bay，`派珀角` → Point Piper；district 只当 LGA 用，suburb 以补上的为准。
3. **换掉 LOT 临时地址**：30 米内已有正式门牌的直接改成正式门牌（抽样 86%），其余保留并标记"临时"。
4. **路名规范**：公路编号写成路名的换成 G-NAF 路名；方位后缀与 G-NAF 对齐；`CLOS` 这类截断类型词补全（全量 25,245 行）。
5. **坐标放错的 0.1%**：用 G-NAF 坐标替换，或在 GU 结果里降权。
6. **门牌找不到的 1.7%**：不急着删。附近没有 G-NAF 点的多是新建，保留；落在同路另一门牌上的，抽样人工看一批再决定。

## 5. 引擎上的改动

体检时发现引擎不认识一批澳洲官方路类型缩写（CIR、ESPL、DVWY、GLN、VW 等，以及门址库里常见的截断写法 CLOS、GLAD）。已经按 Australia Post / G-NAF 的写法补进 AU、NZ 两个市场（只收不会和普通词撞的写法）。AU 开发集上判错（FIX）从 6.0% 降到 5.8%，500 米内从 90.5% 升到 90.7%；NZ 不变；单元测试全部通过。

## 7. 对后续评测的影响

- 底表坐标和 G-NAF 基本一致，所以评测时"判对"可以直接用坐标距离（30 米内算门牌级正确），不用担心底表本身的误差。
- 底表没有用户输入，不能当评测对用。第 15 篇第 4 节的对比测试还是要真实查询日志（用户输入 + GU 结果 + 签收坐标或人工标注）。没有日志时，可以拿补齐后的底表合成带噪声的输入，但要标明是合成数据。
