## 1. 结论

### 1.1 与 Google 实测对比

公司线上评测的 1,000 条查询，Google 做对 854 条；其中 851 条有库内目标门址坐标（0924 包），都是 Google 做对的。这 851 条我们的服务也跑了：收到 geo 的结果，核对层判能不能用，不能用时本引擎兜底。做对 = 直接通过或请用户确认、且离目标 ≤ 100 米。只有 Google 做对的查询有标准答案，所以口径偏向 Google。

| 口径 | 条数 | Google | 我们的服务 | 只用现有 geo | 只用我们的引擎（不带 geo） |
|---|---|---|---|---|---|
| Google 做对的查询 | 851 | 100% | **74.9%** | 65.9% | 38.3% |
| 全部（Google 做错的 146 条记我们全错） | 1,000 | 85.4% | **63.7%** | 56.1% | 32.6% |

## 2. 技术链路

```
输入 → 噪声剥离 → 规范化（统一匹配键） → 混合解析（规则 + CRF，参考数据裁决）
     → 召回：试点城市参考库（地址点 / 道路 / 片区 / 楼宇 / 邮编）；试点城市以外：范围守卫 + 全国门址库
     → 证据打分 → 结论规则树（ACCEPT / CONFIRM / FIX + 粒度 + 原因码）
     → 全国门址库交叉核对（试点结论站不住时） → 校准置信度 → Google AV 格式输出
请求带 geoResult 时：geo 核对层先把 geo 的门址代回原文和参考数据，自洽才直接通过，否则用本引擎的结果
```

| 层 | 代码 | 要点 |
|---|---|---|
| 分发 | `avmvp/router.py`、`avmvp/server.py` | `SG` 走新加坡引擎，其余走多市场引擎；加载引擎时会调用 `Engine.warm()` |
| 新加坡引擎 | `avmvp/validator.py`、`parser.py`、`reference.py`、`noise.py`、`bayes.py` | 逐楼栋验真；贝叶斯只算置信度，不选地址 |
| 多市场配置 | `avmvp/intl/markets.py`、`text.py` | 各国写法（邮编格式、门牌位置、类型词、缩写）全在配置里，引擎里不按国家写逻辑 |
| 解析 | `intl/parse.py`、`intl/crf.py`、`intl/render.py` | CRF 用参考库按各国写法渲染的样本训练，不需要人工标注 |
| 决策 | `intl/engine.py` | 打分、规则树、交叉核对（`_national_cross_check`）、只写门址行时的歧义判断（`_national_unique`）、预热 |
| 试点城市以外 | `intl/coverage.py`、`intl/national.py` | 范围守卫（GeoNames）；全国门址库（磁盘 sqlite） |
| geo 核对 | `intl/geo_check.py`、`geo_text.py`、`geo_free.py` | 有参考库的国家逐字段核对；没有参考库的国家只用原文 + 全国地名表 |
| 输出 / 置信度 | `intl/google.py`、`intl/confidence.py` | 字段与 Google AV 一致；置信度 = 同类结论在开发集上的实际正确率 |

关键设计和依据：

| 设计 | 依据（同一测试集对比） |
|---|---|
| 规则 + CRF 混合解析，参考数据裁决 | 44 国真实地址上都是最好或差 ≤ 0.6 个点；纯 CRF 最差（日本 64.4% vs 90.5%，印尼 26.4% vs 62.2%） |
| 噪声剥离 | 新加坡噪声集：不剥离直接通过 13.8%，剥离后 87.2%；15 国逐类注入噪声，静默错误都是 0 |
| 邮编交叉校验、楼宇名召回、道路拼写纠错 | 去掉分别 −12.7 / −9.7 / −4.9 个点 |
| 规则选地址，贝叶斯只算置信度 | 选地址：规则 99.9%，贝叶斯 97.5–98.6% |
| 道路级直接通过要"邮编印证 + 路名在城内唯一 +（名称一致或片区印证）" | 东南亚 7 国偏差 > 1 公里的静默错误 2.5–4% → 0.2–1.5%（原因码 `ROUTE_NOT_CORROBORATED`）；按市场放宽的规则在 `models/accept_policy.json` |
| 置信度 = 同类结论在开发集上的实际正确率 | 44 国测试集 43,486 条，校准误差 1.2%，AUROC 0.860（`models/confidence_intl.json`） |
| 范围守卫（GeoNames 地名 / 邮编表） | 范围内误判成范围外：真实地址 0.13%、合成 0.02%；配到试点城市同名路的 289 → 21 条 |
| 全国门址库交叉核对（`_national_cross_check`） | 悉尼合成开发集定位对 78.6% → 92.8%，静默错误 1.7% → 0。保护：试点有邮编 / 片区印证不换；原文邮编与全国库不同不换；只靠城市名印证且试点已有门牌 / 道路结论不换；全国库路名是纠错来的最多 CONFIRM。不加保护时葡萄牙静默错误 1.0% → 4.2% |
| 只写门址行、都市圈里有同名同号就请确认（`_national_unique`） | 悉尼只写门址行的静默错误 6.0% → 0；代价是新西兰直接通过 −3.1 个点、葡萄牙 −0.8 |
| geo 核对层 | 模拟 17 国 geo 的 5 种错法，2,065 条错的一条没放行；真实流量见 1.1 |
| 性能：`(nkey, postcode)` 索引、路名比对缓存、召回上限（`TOWN_ROWS` 等）、`Engine.warm()` | P95 约 500 → 28.8 毫秒；10 国 16,000 条只有 4 条结论变化 |

## 3. 其他国家的拓展

### 3.1 加一个国家

1. `avmvp/intl/markets.py` 加一个 `Market(...)`：试点城市框、邮编正则、门牌在路名前还是后、语言、类型词缩写。引擎里不按国家写逻辑。
2. 拉数据并构建：`fetch_markets.py --markets XX`（Overture）→ `fetch_osm_addresses.py`（OSM 门牌，下载源在脚本的 `SOURCES` 里）→ 有政府开放数据就加进 `fetch_extra_addresses.py` → `build_market_reference.py --markets XX` → `fetch_gazetteer.py`（范围守卫）→ `train_market_parsers.py --markets XX`；要在试点城市以外验到门牌，再 `fetch_national.py --markets XX`。
3. 评测和校准：`evaluate_markets.py --markets XX --split dev` 迭代，`fit_accept_policy.py`、`fit_intl_confidence.py` 重拟合，最后跑一次 `--split test`。
4. 第二批 5 国（科威特、巴林、埃及、哈萨克斯坦、多米尼加）就是这样加的：测试集定位对 26.9–52.2%，线上做对 66 → 82 条，静默错误 3 → 3。

### 4.1 方案对照

| 方案 | 数据 | 结果 | 结论 |

### 4.2 改代码前要守的评测规矩

- 开发集迭代，测试集只在最后跑一次（`evaluate_markets.py --split dev|test`；悉尼合成评测按编号哈希分两半）。

- 改了全国库、噪声剥离、解析的通用逻辑，至少回归三项：10 个有全国库的市场（`evaluate_markets.py --markets AU,NZ,DE,ES,NL,CO,BE,PT,PL,AT --parsers hybrid --split dev`）、线上真实返回（`geo_real_eval.py`，再跑 `google_real_compare.py`）、悉尼合成开发集（`base_table_synth_eval.py --split dev`）。
- 改动前后逐条对比用 `scripts/regression_diff.py`（git worktree 检出旧版本，两边各跑一遍）。
- 客户原始地址不进仓库，报告只放汇总；Google 和竞品的结果只用来打分。

### 4.3 运行

- Python 3.11：`python3 -m venv .venv && . .venv/bin/activate && python -m pip install -r mvp/requirements.txt`（统一用 `python -m pip`）。
- 起服务：`cd mvp && python -m avmvp.server --host 0.0.0.0 --markets SG,AU,DE --preload`。`--preload` 启动时加载并预热；10 国全国库全读进页缓存约 17 GB 内存，不够就用 `--markets` 少开几国。
- 环境变量：`AV_MARKETS_DIR`（参考数据目录），`AV_WARM_DB=0`（不预读库文件）。
- Docker：`docker build -t address-validation mvp && docker run -p 8080:8080 -v $PWD/mvp/data:/app/data address-validation`。
- 接口：`/v1/address:validate`、`/v1/address:batchValidate`、`/v1/markets`、`/healthz`，见 [openapi.yaml](openapi.yaml)。
