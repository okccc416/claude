# 09 · 贝叶斯打分：能否替代手工规则？置信度怎么来？

> 问题：用贝叶斯方法（概率匹配）替代规则引擎里人工排定的"证据优先级"，是否更准？能否给每个结论配上可信的置信度？
> 代码：[`mvp/avmvp/bayes.py`](../mvp/avmvp/bayes.py)；评测：[`mvp/scripts/evaluate_bayes.py`](../mvp/scripts/evaluate_bayes.py)；
> 完整报告：[`mvp/reports/bayes_eval_report.md`](../mvp/reports/bayes_eval_report.md)

---

## 1. 结论

| 问题 | 结论 |
|---|---|
| 用贝叶斯**替代规则来选地址**，会更准吗？ | **不会，反而更差。** 标准集 99.9% → 97.5%（朴素）/ 98.6%（联合证据）；噪声集 98.8% → 98.1% |
| 为什么？ | 规则引擎里有大量"结构性推理"：路名里的数字不能当楼栋号、粘连写法有两种切分、长路名优先于被包含的短路名。逐字段打分表达不了这些，要追平规则就得把规则重新编码成特征，意义不大 |
| 那贝叶斯用在哪？ | **给规则的结论配置信度。** 规则负责"选哪个"，贝叶斯负责"有多大把握"。准确率与规则完全一致，并多了一个校准良好的置信度（标准集校准误差 0.002，噪声集 0.010） |
| 置信度在当前测试集上有用吗？ | **能用，但区分度还不够。** 规则在合成数据上几乎从不出错，所以几乎所有结论的置信度都接近 100%。要让置信度真正区分出"哪类结论有风险"，需要用**真实订单的标注数据**来统计 |

**推荐架构：规则选择 + 贝叶斯置信度。** 已接入演示服务器，接口的 `verdict.confidence` 字段即为置信度。

---

## 2. 四种做法的对比（测试集，从未参与训练）

| 做法 | 标准集完全正确率 | 噪声集地址识别率 | 相对规则：改对 / 改错 | 置信度校准误差（标准 / 噪声） |
|---|---|---|---|---|
| 规则（当前） | 99.9% | 98.8% | — | 没有置信度 |
| 贝叶斯选择 · 朴素（字段独立） | 97.5% | 98.1% | 0 / 96；2 / 13 | — |
| 贝叶斯选择 · 联合证据 | 98.6% | 98.1% | 0 / 55；2 / 13 | 0.019 / 0.029 |
| **规则选择 + 贝叶斯置信度** | **99.9%** | **98.8%** | 0 / 0 | **0.002 / 0.010** |

- "改对 / 改错"：与规则相比，最终选中的地址由错变对、由对变错的条数，前一组数字是标准集，后一组是噪声集。
- "置信度校准误差"（ECE）：置信度与实际正确率之间的平均差距，越接近 0 越准。

---

## 3. 为什么贝叶斯"选地址"输给了规则

**做法**：对每个候选地址，逐字段比较输入与候选（邮编、楼栋号、道路、楼宇名），得到"完全一致 / 差一位 / 没填 / 矛盾"等等级。每个等级的证据权重 = log₂(它在正确候选中出现的概率 ÷ 在错误候选中出现的概率)，从开发集统计。权重相加后，所有候选加上"都不是"一起归一化成概率。

**第一版（朴素，字段独立）学到的权重暴露了问题：**

| 字段 | 学到的权重 | 问题 |
|---|---|---|
| 道路完全一致 | +0.1 | 同一条路上的其他楼栋也是"道路一致"，单看道路区分不了对错 |
| 输入没有道路 | **+1.0** | 反而加分：只写楼宇名或邮编的输入，正确候选往往"没有道路" |

也就是说，**有区分度的是字段组合**，比如"楼栋号 + 道路同时一致"，而朴素贝叶斯假设字段独立，把组合关系丢掉了。

**第二版（联合证据）** 把"邮编 × 楼栋号 × 道路"的组合作为整体统计，权重就合理了：三者全一致 +9.0，"没填邮编 + 楼栋和道路一致" +6.1，"楼栋号对不上"基本都在 −6 左右。准确率从 97.5% 升到 98.6%，但仍低于规则，剩下的差距来自两类情况：

- **字段配合的例外**：`Dowell Tuition Centre (Buangkok Crescent)` 的正确答案是"道路一致、没有楼栋号、但楼宇名吻合"。统计上"只有道路一致"的候选几乎都是错的（−7.8），楼宇名那点加分救不回来。
- **切分推理**：`28eOxleY road` 应读作 28E Oxley Road，这是规则引擎在"切分"层面做出的判断。逐字段比对时，28 和 28E 两个候选的特征完全相同，只能五五开。

## 4. 推荐做法：规则选择 + 贝叶斯置信度

**置信度怎么算**：把规则的每个结论归入一个"结论类别"（由组件判定组成，例如"楼栋号确认 · 道路确认 · 邮编推断 · 无多余文字"），置信度 = 该类别在带标注数据里的**实际正确率**。

- **Beta 先验平滑**：样本少的类别不会轻易给出 100%。
- **逐级退回**：没见过的细分类别，退回到更粗一级的类别估计，比如只看楼栋 / 道路 / 邮编的状态。
- **每个置信度都能解释**：例如"历史上同类结论 690 条中对了 690 条"。

**与严格度档位配合**：置信度低于档位门槛时，把"直接通过"降为"请用户确认"，但**不改变选中的地址**。

| 档位 | 直接通过所需置信度 |
|---|---|
| STRICT | ≥ 99% |
| BALANCED（默认） | ≥ 95% |
| LENIENT | ≥ 90% |

## 5. 置信度的校准结果与局限

| 测试集 | 校准误差 ECE | 说明 |
|---|---|---|
| 标准集 | 0.002 | 置信度与实际正确率几乎一致 |
| 噪声集 | 0.010 | "查不到地址（NO_MATCH）"这一类：开发集里 98.7% 真的没有地址，测试集里只有 91.3%。原因是噪声测试集中"两处拼错的真实地址"的比例比开发集高，**说明置信度依赖训练数据的构成** |

**当前局限（重要）：**

1. **区分度不足。** 规则在合成数据上几乎全对，导致几乎所有结论类别的置信度都接近 100%，"按门槛自动通过"的表格在各个门槛下完全一样。只有用真实数据统计，才能看出哪类结论真正有风险，比如"楼栋号是按邮编替换的"、"仅凭楼宇名确定"这些类别。
2. **依赖数据构成。** 真实流量里各类输入的比例与合成数据不同，置信度必须用真实标注数据统计，并定期重新统计。

## 6. 下一步

1. **用 500–1,000 条真实订单的标注样本重新统计置信度**（`ConfidenceModel.fit`），这是让置信度真正有用的前提。
2. **按客户定门槛**：基于真实数据画出"自动通过比例 vs 错误率"曲线，例如"直接通过的错误率 ≤ 0.1%"时能自动通过多少，把门槛做成客户可配的参数。
3. **以后再试"贝叶斯选择"**：等真实数据足够，把楼宇名、切分方式等纳入联合证据，届时再和规则比较。Jev 这类能输出校准概率的模型也可以接入同一套评测，与之对比（见 [08 文档](08-ai-local-model.md)）。

```bash
cd mvp
python scripts/evaluate_bayes.py      # 开发集训练、测试集评测，约 1 分钟
python -m avmvp.server                # 默认加载 models/confidence_sg.json，接口返回 verdict.confidence
```
