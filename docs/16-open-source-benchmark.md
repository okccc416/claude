# 16 · 开源方案对比：libpostal、Addok、Pelias

> 不逆向别家的产品，看公开的白盒：拿最常用的三个开源地址项目，在同样的数据和评测口径下与本方案对比，找可以借鉴的地方。
> 结论先行：三个都没有比本方案好；差距主要不在"定位到哪"，而在"能不能直接通过"——同样的准确率下，开源引擎能自动通过的比例只有本方案的一半左右。可借鉴的只有一处（libpostal 作印尼的兜底解析，测试集复核见第 1 节）。

| 项目 | 是什么 | 许可 | 比什么 |
|---|---|---|---|
| [libpostal](https://github.com/openvenues/libpostal) | 全球地址解析 / 规范化（用 OSM 等数据训练的 CRF），Pelias、很多商业系统的解析层 | MIT | 只换解析：libpostal 拆出的字段送进本方案的召回和验真 |
| [Addok](https://github.com/addok/addok) | 法国国家地址 API（api-adresse.data.gouv.fr）的检索引擎，配法国国家地址库 BAN | MIT | 整条链路，巴黎：政府级地址库 + 开源检索 vs 本方案 |
| [Pelias](https://github.com/pelias) | 最常用的开源地理编码器：libpostal 解析 + Elasticsearch 检索打分 | MIT | 整条链路，悉尼 / 墨尔本：与本方案用同一份参考库，只比算法 |

评测都用开发集（各市场的真实商户地址，与 [13 文档](13-multi-market-product.md) 同一套切分），复核用测试集。脚本：[`oss_parser_eval.py`](../mvp/scripts/oss_parser_eval.py)、[`oss_geocoder_eval.py`](../mvp/scripts/oss_geocoder_eval.py)；报告：[`reports/oss_parser_eval.md`](../mvp/reports/oss_parser_eval.md)、[`reports/oss_geocoder_eval.md`](../mvp/reports/oss_geocoder_eval.md)。

## 1. libpostal：解析层

只换解析这一步，召回、验真、结论规则不变，所以差别全部来自"字段拆得对不对"。三种用法：本方案（规则 + CRF，上线配置）、只用 libpostal、本方案没直接通过时再用 libpostal 拆一次（与本地小模型的级联同一机制，参考数据裁决）。

开发集，44 个市场各 600 条真实商户地址 + 600 条合成地址：

| | 真实地址定位对 | 合成地址定位对 | 真实地址静默错误 | 真实地址直接通过且对 | 每条耗时 |
|---|---|---|---|---|---|
| 本方案 | **81.1%** | **91.7%** | 3.0% | 61.0% | 11 ms |
| 只用 libpostal | 71.8% | 74.0% | 2.2% | 52.3% | 4 ms |
| 本方案 + libpostal 兜底 | 81.3% | 91.5% | 3.0% | 61.4% | 11 ms |

- **libpostal 单独用，没有一个市场比本方案好**：欧洲、澳洲、加拿大差 0–5 个点；中东、东南亚差 10–20 个点；日本几乎不能用（真实地址 8.5%，日文地址它拆不开）；合成地址（各国写法变体）差得更多。原因是本方案的解析拿参考库当词典（道路名、片区名逐个对得上才算），libpostal 是通用模型，不认识当地的路名。
- 静默错误更低只是因为它找到的少、直接通过的少。
- **兜底用法有局部提升**：印尼 +2.5、马来西亚 +1.7、波多黎各 +1.3、墨西哥 +0.7、意大利 +0.7 个点（真实地址），但阿联酋、马来西亚、波多黎各的合成地址反而下降（阿联酋 −4.8）。
- 真实流量（0924 包里本方案 44 个市场的 573 条，不看 geo）：本方案定位对 89 条，只用 libpostal 69 条，兜底 89 条（直接通过且对多 3 条，偏差 > 500 米多 1 条）。

（测试集复核进行中：印尼、马来西亚、波多黎各、墨西哥、意大利。）

## 2. Addok：法国国家地址 API 的做法

法国的国家地址 API 是"政府级地址库 + 开源检索"的典型做法：BAN（法国国家地址库，覆盖全国门牌）+ Addok（检索、打分）。在巴黎（含近郊 92 / 93 / 94 省）用同一批 600 条真实商户地址比，两边各用自己的数据：

| | 定位对（≤ 250 米） | 偏差 > 1 公里 | 自动通过 | 自动通过里定位对 |
|---|---|---|---|---|
| 本方案 | **94.3%** | 2.7% | **89.2%** | 97.8% |
| Addok + BAN | 89.5% | 2.8% | 46.7% | 97.9% |

- 定位能力接近（Top1 差 5 个点）：BAN 本身就是全国门牌，检索也成熟。
- **差在"能不能直接通过"**：Addok 只给 0–1 的相似度分数，没有"门牌、道路、邮编是否相互印证"的判断。要达到和本方案直接通过一样的准确率（约 98%），分数门槛只能放过 46.7%，本方案是 89.2%。这正是本方案验真层（逐字段印证 + 校准）的价值。
- Addok 1.3.2 有一个门牌匹配的缺陷（同一条结果第二次处理时报错），评测里打了补丁。
